# singHarmony2

Rewrite of [How to Sing Harmony](https://sing-harmony.calebhugo.com) on the resound stack.
Live at **https://sing-harmony-beta.calebhugo.com**.

74 hymns in four-part harmony. Pick a part, mute the others, follow the score
as it plays. Notation is engraved live by
[resound-notation](https://www.npmjs.com/package/resound-notation); audio is the
synthesized concert-grand from
[resound-sound](https://www.npmjs.com/package/resound-sound) — no audio assets,
no score images.

## Develop

```bash
npm install
npm run dev       # Vite on http://localhost:5173
npm run build     # production build to dist/
npm run convert   # regenerate public/songs/ from the legacy app data
```

## How it works

- `public/songs/<slug>.json` — one file per hymn in the shared resound note
  schema (`{pitch, length, dotted?, tie?}` per note, four voices, notated
  quarter-note beat timeline). Generated by `scripts/convert.mjs` from the
  legacy parallel-array data in `calebhugo-com/sing-harmony-public/`.
- `src/score.js` — renders the 4-voice open score (one staff per part,
  bracketed, tenor displayed 8va) and layers on part labels, the playback
  cursor (via `data-beat`/`data-voice-id`), click-to-seek, and mute tinting.
- `src/player.js` — beat-clock sequencer driving `Piano.startNote()`. Merges
  ties, honors the song's rit/accel tempo map, and scales dynamics to the
  number of unmuted voices (solo part loud, full choir soft).
- `src/main.js` — song list, controls, URL routing (`?song=slug`).

## Adding songs

There is no editor — write the JSON by hand (or have Claude do it) following
the schema above, drop it in `public/songs/`, and add an entry to
`public/songs/index.json`.
