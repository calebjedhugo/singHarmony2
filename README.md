# singHarmony2

Rewrite of [How to Sing Harmony](https://sing-harmony.calebhugo.com) on the resound stack.
Live at **https://sing-harmony-beta.calebhugo.com**.

74 hymns in four-part harmony. Pick a part, mute the others, follow the score
as it plays. Notation is engraved live by
[resound-notation](https://www.npmjs.com/package/resound-notation); audio is the
synthesized concert-grand from
[resound-sound](https://www.npmjs.com/package/resound-sound) — no audio assets,
no score images.

## Develop

```bash
npm install
npm run dev       # Vite on http://localhost:5173
npm run build     # production build to dist/
npm run convert   # regenerate public/songs/ from the legacy app data
```

## How it works

- `public/songs/<slug>.json` — one file per hymn in the shared resound note
  schema (`{pitch, length, dotted?, tie?}` per note, four voices, notated
  quarter-note beat timeline). Generated by `scripts/convert.mjs` from the
  legacy parallel-array data in `calebhugo-com/sing-harmony-public/`.
- `src/score.js` — renders the four-voice close score (S+A on the treble staff,
  T+B on the bass staff, braced) and layers on the playback cursor (via
  `data-beat`/`data-voice-id`), click-to-seek, ribbon follow, and mute tinting.
- `src/player.js` — adapter over resound-sound's `Sequencer`, which reads the
  song's note arrays untouched. Holds only app policy: which piano and when to
  warm it, the A-B loop buttons, and dynamics scaled to the number of unmuted
  voices (solo part loud, full choir soft).
- `src/main.js` — the shell: two views and `?song=slug` routing. The controls
  themselves are in `src/ui/` — `songList.js` (list + search), `controls.js`
  (transport, tempo, loop, verses, SATB chips), `layout.js` (page/ribbon mode,
  orientation, menu) — and `src/catalog.js` does the fetching.

## Adding songs

There is no editor — write the JSON by hand (or have Claude do it) following
the schema above, drop it in `public/songs/`, and add an entry to
`public/songs/index.json`. Then run `npm test`: it renders every song through
resound-notation and builds its playback timeline, so a malformed pickup,
a note overrunning its measure, an unterminated tie, or an index entry that
disagrees with the song file all fail there instead of in front of a singer.

## Test

`npm test` (jest + jsdom). Song data is judged by the real libraries
(`src/songs.render.test.js`, `scripts/songs.test.mjs`); the app's own suites
cover the measure grid, the player adapter, and the controls — the UI tests
mount the real `index.html` body, so a renamed id fails a test rather than
quietly unwiring a button.
